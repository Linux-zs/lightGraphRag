# LightGraphRAG 使用手册

本文记录 LightGraphRAG Workbench 的常规使用流程。内容按页面组织，覆盖模型配置、知识库管理、文档索引、问答、召回调试、知识图谱治理和系统运维。

## 一、基本概念

### 1. 知识库

知识库对应 LightRAG 的一个 workspace。每个知识库有独立的上传目录、解析文本、索引、manifest、图谱治理配置和会话列表。

知识库名称只支持字母、数字、下划线和短横线，长度 1 到 64 位。

### 2. 上传、索引和状态

`uploaded` 表示原始文件已经保存，并完成文本解析。此时还不能被 LightRAG 问答使用。

`processing` 表示后台正在写入 LightRAG，包括文本索引、实体抽取和关系抽取。

`processed` 或 `indexed` 表示文档已经进入 LightRAG，可用于召回和问答。

`failed` 表示索引失败。需要查看任务错误、后端日志或重新索引。

### 3. Chunk

Chunk 是文档切分后的文本块。问答、召回和引用都围绕 chunk 展开。切块过小会丢上下文，切块过大会影响召回精度和模型输入长度。

默认参数：

```text
chunk_size: 512
chunk_overlap: 50
separators: \n\n, \n, 。, ！, ？, ；, 空格
```

### 4. 召回调试

召回调试有两个入口：

- 生成上下文：调用 LightRAG 的上下文生成能力，查看最终送入回答模型的资料。
- 文本召回：查看原始向量召回结果，并和 Rerank 后排序对比。

### 5. 抽取规则

抽取规则用于引导 LightRAG 抽取实体和关系。规则不是普通问答提示词。

抽取模式有三种：

- 辅助：通用抽取优先，规则只做归类和纠偏，适合大多数知识库。
- 增强：更重视领域规则，但不会压制明显重要的实体关系。
- 严格：接近白名单，适合结构规范的领域知识库；非领域文档可能抽不出图谱。

### 6. 问答提示词

问答提示词控制最终回答风格。参考资料由系统自动拼接，提示词里只需要说明回答规则、引用规则和资料不足时的行为。

提示词模板可以复用到多个知识库，但每个知识库最终保存的是自己的提示词内容。

## 二、启动系统

### 1. 后端

```powershell
uv sync --locked --all-groups
uv run python -m src.app.cli server --no-reload
```

默认监听：

```text
http://127.0.0.1:8101
```

OpenAPI：

```text
http://127.0.0.1:8101/docs
```

### 2. 前端

```powershell
cd frontend
npm ci
npm run dev
```

默认访问：

```text
http://127.0.0.1:5173
```

### 3. 远程访问

本地回环访问不需要令牌。绑定到非本机地址时必须设置：

```powershell
$env:TDX_APP_API_TOKEN="replace-with-a-random-token"
uv run python -m src.app.cli server --host 0.0.0.0 --no-reload
```

外部请求需要带：

```text
X-App-Token: replace-with-a-random-token
```

## 三、模型设置

进入左侧“模型设置”页面。

### 1. 新增连接档案

填写：

- 连接名称：例如 `SiliconFlow`、`DeepSeek`、`Local Ollama Proxy`。
- API 地址：OpenAI-compatible 地址，例如 `https://api.siliconflow.cn/v1`。
- API Key：远端模型一般必须填写。本地服务可为空。

操作顺序：

1. 输入 API 地址和 API Key。
2. 点击“发现模型”。
3. 确认模型列表返回正常。
4. 点击“保存连接”。

API Key 保存后不会回显，只显示脱敏预览。

### 2. 绑定模型用途

模型绑定分为三类：

- 大语言模型：用于问答生成、会话标题和图谱修正建议。
- 嵌入模型：用于文档索引和文本召回。
- Rerank 模型：用于召回结果重排序，可关闭。

每类模型都可以选择不同的连接档案和模型名称。

嵌入模型需要填写：

- 向量维度，例如 `1024`。
- 单条嵌入最大字符，例如 `700`。

保存绑定前建议分别点击“测试”。嵌入测试会返回维度，维度变化后需要重建索引。

### 3. 问答提示词

在“问答提示词”区域：

1. 选择当前知识库。
2. 选择提示词模板，或直接编辑文本框。
3. 点击“保存当前知识库提示词”。

可用操作：

- 另存为模板：把当前提示词保存成可复用模板。
- 更新模板：更新当前自定义模板。内置模板不可覆盖。
- 删除模板：删除自定义模板。不会清空已经保存到知识库的提示词内容。

## 四、知识库管理

知识库选择在左侧顶部。切换知识库后，问答、召回调试、知识图谱和系统状态都会指向同一个知识库。

### 1. 新建知识库

点击知识库选择器旁的新增入口，输入名称并创建。

名称规则：

```text
1-64 位字母、数字、下划线或短横线
```

示例：

```text
tdx_default
butterfly_test
supply_chain_2026
```

### 2. 上传文档

进入“知识库管理”页面，上传文件。

前端默认支持：

```text
txt, md, pdf, docx
```

上传完成后会显示：

- 文件名
- 类型
- 字符数
- 文本预览

如果上传同名文件并内容发生变化，旧索引会被移除，需要重新索引。

### 3. 查看和编辑原始文本

上传后可以点击“查看/编辑原始文本”。

适用场景：

- PDF 解析出现多余换行。
- DOCX 解析后目录或页眉混入正文。
- 想删除不适合索引的无效内容。

保存原始文本后，旧索引会失效，需要重新预览并确认索引。

### 4. 切块预览

调整切分配置后点击“预览切分”。

重点检查：

- 每个 chunk 是否有完整语义。
- 是否出现大量只有编号、变量、页眉页脚的文本块。
- chunk 数是否明显异常。

普通技术文档可先使用默认参数。短文本可以适当降低 `chunk_size`。

### 5. 确认索引

点击“确认索引”后会创建后台任务。

任务状态：

```text
queued      等待执行
running     正在执行
succeeded   全部成功
partial     部分成功
failed      失败
cancelled   已取消
```

索引过程包括：

1. 读取当前知识库的图谱抽取规则。
2. 调用 LightRAG 写入文档。
3. 生成 chunk、实体和关系。
4. 更新 manifest 状态。

任务进度会持久化到 `data/index_tasks/`。切换页面后再回来，前端会尝试恢复最近任务。

### 6. 批量索引

勾选多个文档后点击“批量索引”。

批量索引是顺序处理。某个文档失败时会记录错误，后续文档仍可能继续执行。

### 7. 删除文档

删除文档会执行：

1. 从 LightRAG 删除对应 doc_id。
2. 删除上传源文件。
3. 删除解析后的 raw text。
4. 检查知识图谱是否还有该文档残留引用。
5. 如果发现图谱残留，尝试触发当前知识库重建任务。

删除不会影响其他知识库。

## 五、知识库问答

进入默认对话页面。

### 1. 选择知识库

左侧顶部显示当前知识库。所有问答只使用当前知识库的索引和图谱。

切换知识库后，会话列表也会切换到该知识库自己的会话。

### 2. 新建对话

点击左侧“新建对话”。会话标题会根据首轮问题生成；模型不可用时会退回默认标题。

### 3. 对话设置

输入框上方可以打开对话设置。

可设置：

- 知识库。
- 回答模型。
- Temperature。
- Top-P。
- Max Tokens。
- Frequency Penalty。
- Presence Penalty。
- LightRAG mode。
- 图谱 Top-K。
- 文本块 Top-K。
- Rerank 开关。

检索模式常用值：

```text
mix      默认，综合图谱和向量上下文
hybrid   混合检索
local    偏实体局部上下文
global   偏全局图谱上下文
naive    基础文本检索
```

### 4. 回答结果

回答下方有：

- 复制：复制助手回答。
- 查看上下文：查看本轮引用的文本片段。
- 查看证据链：查看本轮命中的实体、关系和文本块。
- 重新提问：用同一问题重新生成回答。

引用文档默认折叠。展开后可以看到文档名、chunk 序号和摘录。

证据链默认折叠。展开后可以看到图谱节点、关系和引用 chunk。

### 5. 无关问题

系统应只依据知识库上下文回答。资料不足时应回答“知识库上下文不足”。

如果明显无关的问题仍返回知识库内容，按以下顺序检查：

1. 到“召回调试”查看是否命中了无关 chunk。
2. 降低 `top_k` 和 `chunk_top_k`。
3. 检查问答提示词是否明确要求资料不足时拒答。
4. 检查知识库里是否存在过短或噪声 chunk。

## 六、召回调试

进入“召回调试”页面。

### 1. 生成上下文

该模式调用 LightRAG 的上下文生成能力，展示最终送给回答模型的上下文。

适合排查：

- 问答为什么引用这些文档。
- 图谱实体和关系是否进入上下文。
- 某个问题为什么回答为空。
- 无关问题为什么仍然命中文档。

可调整：

- 检索模式。
- 图谱 Top-K。
- 文本块 Top-K。
- Rerank 开关。

### 2. 文本召回

该模式展示向量召回和 Rerank 排序。

页面会显示：

- 向量原始排序。
- Rerank 排序。
- 向量分数。
- Rerank 分数。
- 排名上升、下降或持平。

适合排查：

- 语义相近词是否能召回。
- Rerank 是否把更相关文本排到前面。
- 文档切块是否影响命中。

### 3. 判断召回是否正常

正常情况：

- 问题中的核心实体或同义词能命中相关 chunk。
- Rerank 后更完整、更准确的 chunk 排名靠前。
- 无关问题命中较少或命中内容明显不足。

异常情况：

- 所有问题都命中同一批 chunk。
- 只有文件名、编号或变量被命中。
- Rerank 后相关文本反而大幅后移。
- 上下文里没有 Document Chunks。

## 七、知识图谱

进入“知识图谱”页面。

页面包含：

- 图谱总览。
- 抽取规则。
- 实体治理。
- 关系治理。
- 修正建议。

### 1. 图谱总览

可查看当前知识库图谱节点和关系。

如果没有图谱数据：

1. 确认文档已索引成功。
2. 检查模型是否具备稳定实体关系抽取能力。
3. 检查抽取规则是否过于严格。
4. 重新索引文档。

### 2. 抽取规则

抽取规则由以下内容组成：

- 抽取模式。
- 实体类型偏好。
- 关系类型偏好。
- 术语和别名表。
- 抽取提示词。
- 抽取参考文件。

系统内置模板包括：

- 通达信运维知识库。
- 通用知识库。
- 供应链/风险分析。

切换规则后，只影响后续上传和重新索引。已经索引过的文档不会自动按新规则重建图谱。

### 3. 抽取参考文件

参考文件用于图谱治理，不进入普通问答召回。

支持：

```text
txt, md, json, yaml, yml, csv
```

适合存放：

- 实体命名规范。
- 关系类型说明。
- 术语表。
- 领域样例。
- 不应抽取的噪声规则。

### 4. 实体治理

可操作：

- 搜索实体。
- 编辑实体名称、类型、描述。
- 新增实体。
- 删除实体。
- 合并实体。

合并实体时，可以搜索并复选多个来源实体，再选择一个目标实体。

### 5. 关系治理

可操作：

- 搜索关系。
- 编辑关系描述、关键词和权重。
- 新增关系。
- 删除关系。

新增关系时，起点实体和终点实体可从已有实体中搜索选择。

### 6. 修正建议

输入自然语言指令，让模型基于当前图谱、抽取规则和参考文件生成候选变更。

示例：

```text
检查当前图谱中无意义编号实体，建议删除；合并含义相同的供应商实体；补充药厂和供应商之间的供应关系。
```

生成后需要人工勾选，再点击应用。不会自动直接改图谱。

## 八、系统状态

进入“系统状态”页面。

可查看：

- 文档总数。
- Chunk 总数。
- 图谱节点。
- 图谱关系。
- 嵌入模型。
- LightRAG Workspace。
- LightRAG 目录大小。
- 嵌入维度。

### 1. 重建索引

“重建索引”只处理当前知识库。

流程：

1. 清空当前知识库的 LightRAG 索引和 manifest。
2. 保留当前知识库上传目录里的原始文档。
3. 重新导入这些文档。
4. 重放人工图谱治理记录。

适用场景：

- 更换嵌入模型。
- 修改抽取规则后想重建图谱。
- 删除文档后需要清理图谱残留。
- 索引状态异常。

### 2. 清空索引

“清空索引”默认保留上传文档，只删除 LightRAG 索引和 manifest。

清空后需要重新索引，问答才会恢复。

## 十、排障

### 1. 模型发现 401

原因通常是 API Key 无效、没有保存到连接档案，或当前 API 地址不支持 `/v1/models`。

处理：

1. 在“模型设置”重新输入 API Key。
2. 保存连接。
3. 点击刷新模型列表。
4. 分别测试大语言、嵌入和 Rerank 模型。

### 2. Chat model test failed: Illegal header value

通常是空 API Key 被当成 Bearer Token 传入。当前代码已避免发送空 Authorization，但已有连接档案仍需要保存有效 API Key。

### 3. 上传文件提示 Unsupported file type

前端默认支持 `txt`、`md`、`pdf`、`docx`。

`.doc` 不是 `.docx`，当前不支持。需要先用 Word 或 LibreOffice 转成 `.docx`。

### 4. 索引长时间 processing

可能原因：

- 模型服务响应慢。
- 文档虽然短，但实体关系抽取请求卡住。
- Rerank 或 embedding 服务超时。
- 后端任务被取消或进程重启。

检查顺序：

1. 看页面任务进度和当前文档。
2. 看 `data/logs/app.log`。
3. 检查模型设置里的测试是否通过。
4. 必要时取消任务后重新索引。

单文档索引默认超时：

```text
TDX_INDEX_DOC_TIMEOUT_SECONDS=180
```

### 5. 上下文预览有数据，问答却说找不到文档

检查：

1. 问答页当前知识库是否和召回调试页一致。
2. 问答设置里的 `top_k`、`chunk_top_k` 是否过低。
3. 回答模型是否能正常生成。
4. 当前提示词是否过度严格。
5. `data/logs/app.log` 是否有 answer guard 或模型异常日志。

### 6. 回答出现孤立数字或奇怪字符

可能来源：

- 原文 chunk 本身有噪声。
- 模型输出了裸引用编号。
- 流式输出中途被质量检查拦截。

处理：

1. 展开引用文档，查看对应 chunk。
2. 到“查看上下文”确认送入模型的资料。
3. 编辑原始文本删除噪声后重新索引。
4. 调整问答提示词，要求不要输出孤立编号。

### 7. 图谱抽取不准

处理顺序：

1. 抽取模式先用“辅助”。
2. 使用通用知识库模板，不要误用强领域模板。
3. 补充实体类型偏好和关系类型偏好。
4. 添加抽取参考文件。
5. 重新索引文档。
6. 用实体治理和关系治理人工修正。

### 8. 修改模型后旧知识库不可用

嵌入模型配置变化会导致旧向量索引不兼容。进入“系统状态”重建当前知识库。

需要保留完整本地知识库时，备份：


## 十二、推荐使用流程

新建知识库时按这个顺序操作：

1. 在“模型设置”保存并测试模型连接。
2. 创建知识库。
3. 进入“知识图谱”选择合适抽取规则，普通文档优先用“通用知识库”和“辅助”模式。
4. 上传文档。
5. 查看原始文本，必要时清理噪声。
6. 预览切块。
7. 确认索引。
8. 用“召回调试”测试 2 到 3 个典型问题。
9. 用问答页正式提问。
10. 如果图谱不准，再回到“知识图谱”治理并重建索引。
